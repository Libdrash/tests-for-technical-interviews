## 📌 О репозитории

Этот репозиторий содержит тестовые задания для frontend-разработчиков разных уровней.

Задания помогают проверить не только знание синтаксиса, но и то, как кандидат думает, работает с данными, пишет React-компоненты, обрабатывает состояния и взаимодействует с API.

Репозиторий можно использовать:

- кандидатам — для подготовки к техническим собеседованиям;
- менторам — для обучения и практики;
- тимлидам — для проверки навыков frontend-разработчиков;
- интервьюерам — как базу для тестовых заданий.

## 🧩 Что внутри заданий

Обычно задания состоят из нескольких частей:

### 1. Логика

Работа с массивами, объектами, группировкой данных, сортировкой и вычислениями.

Пример навыков:

- `map`;
- `reduce`;
- `forEach`;
- работа с объектами;
- агрегация данных;
- сортировка.

### 2. React

Создание компонента с реальной пользовательской логикой.

Пример навыков:

- `useState`;
- `useEffect`;
- controlled inputs;
- отображение списков;
- карточки;
- loading/error состояния.

### 3. API / GraphQL

Работа с внешним API через `fetch`.

Пример навыков:

- POST-запросы;
- GraphQL query;
- variables;
- обработка ответа;
- обработка ошибок.

## 🚀 Как проходить задания

1. Открой нужный `.md` файл.
2. Внимательно прочитай условия.
3. Создай отдельный проект или файл для решения.
4. Сначала реши базовую часть.
5. Потом улучши решение:
   - добавь типизацию;
   - обработай edge cases;
   - сделай аккуратный UI;
   - проверь ошибки;
   - убери лишний код.

---

## 💡 Напутствие кандидатам

Тестовое задание — это не экзамен на идеальность.

Здесь важно показать, как ты думаешь:

- умеешь ли разбить задачу на части;
- понимаешь ли данные, с которыми работаешь;
- можешь ли написать читаемый код;
- не забываешь ли про состояния загрузки и ошибок;
- умеешь ли объяснить свои решения.

Не обязательно делать “самое умное” решение.  
Лучше сделать понятное, аккуратное и рабочее.

---

## ✅ Что особенно ценится

- чистый и читаемый код;
- нормальные названия переменных;
- понятная структура компонентов;
- отсутствие лишней магии;
- базовая типизация;
- обработка пустых данных;
- обработка ошибок;
- аккуратный UI;
- умение объяснить, почему решение сделано именно так.
